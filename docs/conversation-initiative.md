# 多条回复与随机主动聊天

NapCat QQ 的直接回复默认优先用 1～4 条短消息连发，条间随机间隔 0.8～2.4 秒，不需要用户先要求“分条”。模型用 `messages` 数组表达独立气泡，并减少普通聊天的符号；旧的单条 `message` 格式继续兼容。发送层也会将合并的聊天文本按自然句尾、换行或明显分隔拆开，例如“修好了？我这边看着能喘气了”会产生两次独立发送。短答可以只有一条，不强行凑条数。

网址、行内代码、完整中文引用、代码块、命令和结构化列表保留格式；超过四段时将余下内容合入第四条，不丢句子。消息仍经 Controller 的同一个动作出口，保持事件去重；某条发送失败后停止这一批余下消息，不重发结果不确定的 QQ 消息。同一会话的路由串行执行。工具结果的后续回复也支持分条。

ESP32 语音和官方 QQ 将数组合成一条完整回复，避免覆盖当前语音或触碰官方回复序列限制。独立 Cognitive Core HTTP 返回动作列表；实际分条投递由嵌入式 Controller 完成。

## 随机触发

随机主动聊天由现有 systemd 管理的中控心跳执行，无需额外进程或 cron。它独立于旧 `autonomous_action_enabled` 启发式开关。新版配置默认开启 `cognitive_core.proactive.enabled`。

升级后先通过 NapCat QQ 私聊一次，系统才有可信的发送目标。默认选最近一次私聊的对象与同一会话历史；官方 QQ 和设备消息不会注册主动私聊目标。多用户使用时注意：这是当前应用的最近私聊目标策略，并非向每位联系人轮流发送。

对话空闲至少 5 分钟后，首次检查会安排一个 15～60 分钟后的随机时刻；后续触发间隔同样随机，受 60 秒心跳精度影响。每次从近期话题、未完问题、共同细节、已记录兴趣、跨记忆联想、换角度、轻松回扣和当前情景等思考角度中随机选一项，并冷却最近五类角度；有可用兴趣线索时加入候选。线索只是启发，模型会结合实际 MMTR 召回和最近对话生成新话题，也可以选择本次不发。时间只作轻量背景，不会自动变成吃饭或睡觉话题。

本地时间默认 Asia/Shanghai。凌晨 0～8 点不主动联系，每天最多 8 次主动思考批次，每批最多 4 条消息；3 天未有新私聊就停止主动联系。活跃会话、无模型、无发送路由会跳过。生成失败不向用户主动推送错误提示。下一次时刻和当日批次次数存入认知数据库，重启不清零；生成或发送失败也消耗该批次，避免故障时反复骚扰。

主动思考不把吃饭、睡觉、玩手机、写代码当作默认话题，不调用工具、不创建计划，也不把随机场景当成经历写入长期记忆。思维核心只保存短事件说明和可审查的决策摘要。正常消息投递继续使用现有授权出口。

## 配置

在 `data/.config.yaml` 按需覆盖后重启中控：

```yaml
cognitive_core:
  reply_delivery:
    min_gap_seconds: 0.8
    max_gap_seconds: 2.4
  proactive:
    enabled: true
    timezone: Asia/Shanghai
    min_interval_seconds: 900
    max_interval_seconds: 3600
    min_idle_seconds: 300
    quiet_start_hour: 0
    quiet_end_hour: 8
    max_daily_starts: 8
    contact_max_age_seconds: 259200
    topic_cooldown_count: 5
```

设 `enabled: false` 关闭随机主动联系，回复分条仍保留。静默起止小时相同表示不设静默时段。旧私有配置中如已有同名字段，会按私有值优先合并。

云端更新：

```bash
cd /home/oii
sudo bash auto-update.sh run
```

`/memory.html` 的同一会话时间线会出现“随机主动思考”，可查看实际激活的记忆、目标引用和决策摘要。历史回复保留所有生成的分条文本；是否送达以 Controller 的动作结果为准。

验证使用可控时钟和测试模型，覆盖分条顺序、失败停止、事件去重、工具回执、时段话题、同会话历史、随机下一次时刻、重启保留、每日上限与换日、静默和空闲、并发触发、不写入虚构经历、后台失败不推送。尚未用生产 QQ、设备或真实模型实测主动投递。
